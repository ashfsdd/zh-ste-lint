# zh-ste-lint

中文受控语言结构检查器。把 **ASD-STE100**（航空维修领域受控英语，Issue 9）的中文五条做成可以机器执行的检查。

一句话：一段文字喂进去，告诉你哪几句太长、哪句塞了好几件事、哪句是客套话。

```bash
zh-ste-lint 稿子.md

=== 稿子.md ===
  句子 198 条｜平均 7.5 字｜最长 20 字｜上限 30
  硬违规 0 条｜提示 1 条
```

## 什么是「航空手册体」

ASD-STE100 是航空维修行业的技术文档写作规范：飞机维修手册要交给全世界不同母语的地勤和机务看，
一个词有歧义就可能出事故，所以它把英文压缩成受控语言——句子短、一句一事、用词统一、必须主动语态、
不确定就写明不确定。本项目把它换算成中文五条，做成可自动执行的检查器。

## 为什么有这个

| 现状 | 问题 |
|---|---|
| 英文世界已有成熟的 STE 检查器 | 对中文**完全失效**：中文段落会被当成 1 个词，等于查不出问题 |
| 中文侧的排版检查工具 | 只查标点、中英文空格，**不查句长** |
| 手工审稿 | 长句和客套话肉眼容易滑过去 |

这个工具补的就是中间那格：**中文 + 句子级结构检查**。

## 安装

```bash
npm install -g zh-ste-lint
```

从源码用：

```bash
git clone https://github.com/ashfsdd/zh-ste-lint.git
cd zh-ste-lint
npm install
npm link          # 可选，让 zh-ste-lint 命令全局可用
```

## 用法

```bash
zh-ste-lint <文件...>                # 检查一个或多个文件
cat 稿子.md | zh-ste-lint            # 从标准输入读
zh-ste-lint --max 25 <文件>          # 收紧句长上限（默认 30）
zh-ste-lint --json <文件>            # 机器可读输出，接 CI 或自己的脚本
```

退出码目前始终为 0，是否卡流水线由你自己按 JSON 里的 `hard` 字段判断。

## 检查什么

| 规则 | 触发条件 | 严重度 |
|---|---|---|
| `long-sentence` | 单句超过上限（默认 30 字） | 硬 |
| `multi-idea` | ≥3 个逗号且超过 20 字 | 提示 |
| `hidden-actor` | 含「被」字句，主语被藏起来 | 提示 |
| `filler` | 命中客套话词表（16 个，如「一般来说」「视情况而定」「建议咨询」） | 硬 |
| `marketing-adjective` | 命中营销形容词词表（11 个，如「炸裂」「丝滑」「yyds」） | 提示 |

「硬」= 建议必改；「提示」= 你自己判断，**标题、封面文案、钩子段请直接忽略这两条提示**。

## 实测样例

AI 腔文本（`samples/ai-slop.txt`）：

```
=== samples/ai-slop.txt ===
  句子 1 条｜平均 112.0 字｜最长 112 字｜上限 30
  硬违规 3 条｜提示 1 条
  ✗ [long-sentence] 句子 112 字（上限 30）。拆成两句，一句一事。
  ! [multi-idea] 5 个逗号、112 字，可能一句塞了多件事。逐件拆开。
  ✗ [filler] 客套话/填充语「需要特别指出的是」。要么给确定答案，要么直接说不确定。
  ✗ [filler] 客套话/填充语「建议用户」。要么给确定答案，要么直接说不确定。
```

受控语言文本（`samples/controlled-zh.txt`，124 句）：

```
=== samples/controlled-zh.txt ===
  句子 124 条｜平均 8.1 字｜最长 19 字｜上限 30
  硬违规 0 条｜提示 2 条
  ! [hidden-actor] 含"被"字句，主语被藏起来。改成"谁去做某事"。
      中文里的被字句常把主语藏起来。
```

两条提示都来自样本在讲解「被」字句时举的例子，属正常报出。

## 已知边界（重要）

1. **只认 `。！？` 结尾**。用 `；` 串起来的长句会被算成一句（上面那个 AI 腔样本就是这种情况，`；` 一路串到 112 字，正好命中长句规则）。**字幕稿要先去掉时间戳、用 `。` 连接**再喂进来。
2. **只查结构，不查事实**。一句话写得再合规，内容是错的它也管不了。
3. **30 字是中文换算值**，不是原版英文的 ≤20 词。真正的目标是「一句一事实」，别把 30 字当 KPI 硬抠。
4. **客套话词表和营销词表是需要持续维护的资产**，遇到漏网的欢迎提 issue 或直接改 `zh-ste-lint.js` 里的两个数组。
