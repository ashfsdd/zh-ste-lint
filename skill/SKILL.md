# 航空手册五条 · 场景路由约束

把航空维修手册的写法规则（ASD-STE100）中文化后，按内容场景路由成默认约束。
上游规范 ASD-STE100（Issue 9，2025-01）已核实：53 条写作规则 + 约 900 个批准词 +
约 1200 个强制替换词；程序句 ≤20 词、描述句 ≤25 词、段落 ≤6 句、禁用分号、必须主动语态。

## 一、五条原文

1. 每个句子不超过 **30 个字**（原版为英文 ≤20 词，此为中文换算）
2. 一个句子只讲一件事
3. 同一个东西，从头到尾用同一个词
4. 主动语态：谁去确认、谁去执行，要写清楚（禁"被"字句藏主语）
5. 不确定的地方，直接说不确定

## 二、场景路由表（默认生效的核心）

按产物类型决定开哪几条，**不做全局一刀切**：

| 场景 | 触发信号 | 开启条目 | 说明 |
|---|---|---|---|
| S1 攻略/步骤/机制整理 | 攻略、怎么打、机制、流程、参数、步骤 | **全五条** | 纯信息段，一句一事收益最大 |
| S2 解说稿/口播稿 | 解说稿、脚本、口播、文案 | **第 2/3/4 条** | 不上第 1 条字数限制，保留情绪铺陈 |
| S3 直播大纲/待办/周报 | 大纲、待办、周报、总结、复盘 | **全五条** | 纯信息，越短越省观众精力 |
| S4 查资料/核实事实 | 查一下、是不是、真的吗、核实、确认 | **第 4 + 5 条** | 治幻觉最关键的两条 |
| S5 AI 成稿体检 | 检查、审一下、改稿、体检、过一遍 | **全五条（当 linter）** | 回报最高的用法 |
| S6 标题/封面/钩子 | 标题、爆款、钩子、封面、前三秒 | **全关** | STE 禁营销形容词，会杀死点击率 |
| S7 创意/头脑风暴 | 想点子、脑暴、整活、反转设计 | **全关** | 要的就是铺陈和跳跃 |

## 三、全局默认项（无需触发，长期生效）

**第 5 条「不确定就说不确定」是无条件默认。** 它是五条中唯一不伤风格的一条，
治的是 AI 幻觉与客套糊弄。对内容创作者是刚需——被观众当场抓错比说错话更掉粉。

配套话术（直播/解说现场）：
- 「这块我不确定，不瞎说，下播查清楚再讲。」
- 「有两种说法，我说我更有把握的那种，另一种可以补充。」
- 「这个我没实测过，只是看别人这么弄，你们当参考。」

## 四、硬边界（违反即失效）

1. **不约束助手回复的对话排版。** 本技能约束的是**内容产物**，不是聊天格式。
   用户另有「排版铁律」（小标题配表情、加粗重点），两者分层，不可互相覆盖。
2. **不碰标题、封面、前三秒钩子、整活段、爽文反转、情绪高潮。** 这些靠营销形容词
   和长句铺陈活着，STE 会直接杀死点击率。
3. **第 1 条的 30 字是参考线不是死线。** 中文该抓的本质是「一句一事实」；
   一句话塞两件事，25 字也该拆。梗、专有名词、情绪句天然破线，不追 0 违规。

## 五、与 deai-promax 的分工与叠加

两者治的不是一个病，可叠加，**顺序固定：先五条，后 deai-promax**。

- 五条治「信息密度」：一句一事、主语明确、名词一致
- deai-promax 治「AI 腔」：词汇偏好、句长均匀度、破折号密度、三段式同构

先理顺信息，再去 AI 味。反过来会去完味还要再拆句。

## 六、标准工作流

### 生成类任务（S1/S2/S3）
1. 按路由表确定开启条目，把对应条目原文贴进提示词
2. 明确告知"仅约束信息段，人设段/梗/反转不受限"（S2 必须）
3. 生成后自检：最长句、一句多事处、同物异名处

### 体检类任务（S5，优先推荐）
1. 收下用户已成稿，**不重写全文**，只标问题
2. **中文稿先跑检查器**（见第八节），拿到机械违规清单，再补需要人判断的部分
3. 输出格式：`序号 | 违规条目 | 原句 | 改法`
4. 五类必查：超长句 / 一句多事 / 同物异名（列 原名→别名 对照表）/ 藏主语 / "一般来说"类糊弄
5. 给结论：问题句 ≤3 个 = 信息段已干净；>5 个 = 建议把模板 A 常态化

### 事实类任务（S4）
1. 第 5 条置顶：查不到就说查不到，不用"一般来说"兜底
2. 第 4 条落地：区分"我确认的"和"我推测的"，分别标注

## 七、量化标尺

- 参考基准：受控语言样例文本实测 124 个语句，**平均 8.1 字，最长 19 字，
  超 30 字句子 0 句**（极端纪律，非"尽量短"）
- 日常口语中文一般 15–25 字/句
- 自检线：**一句话超过 30 字就拆**，先只抓这一条就能见效
- 基准样本已随技能附带：`scripts/benchmark-controlled-zh.txt`（可直接喂给检查器对比）

## 八、现成方案复用（别再自己重写）

按语言分流：

| 语言 | 情况 | 处置 |
|---|---|---|
| 英文 | 已有成熟开源 STE 检查器（MIT 许可，自带完整检查逻辑） | 需要时自行检索英文 STE linter，不必自研 |
| 中文分句 | 有成熟开源分句组件 `sentence-splitter`（MIT 许可） | 直接复用，`。！？` 切分已实测正确，勿自写正则 |
| 中文检查 | **自研，无现成** | 用本技能自带 `scripts/zh-ste-lint.js` |

**为什么中文要自研**：英文 STE 检查器不切中文词，整段会被算成 1 个词，等于查不出问题。
中文这一层确实没有现成的检查器，但硬骨头（分句）直接复用成熟组件，
只自研了中文字数统计、客套话词表、「被」字句检测和一句多事启发。

### 运行中文检查器

```bash
# 依赖：node + sentence-splitter（一次性安装）
cd ~/.workbuddy/binaries/node/workspace && npm install sentence-splitter

export NODE_PATH=~/.workbuddy/binaries/node/workspace/node_modules
node ~/.workbuddy/skills/航空手册五条/scripts/zh-ste-lint.js 稿子.txt
node ~/.workbuddy/skills/航空手册五条/scripts/zh-ste-lint.js --max 25 稿子.txt   # 自定义上限
```

检查项与严重度：
- **硬违规**：句长超上限、客套话/填充语（"一般来说""旨在""为了更好地""建议用户"…）
- **提示**：一句多事（≥3 逗号且 >20 字）、「被」字句藏主语、营销形容词（信息段该删、标题段可留）

**已知限制**：只认 `。！？` 结尾的散文。字幕稿/时间戳稿需先去掉时间戳并用 `。` 连接，
否则整篇被当成一句（实测踩过）。用 `；` 串写的长句同理会被算成一句（正好命中长句规则）。

### 独立开源仓库（2026-10-26 已发布）

同一检查器已整理成 MIT 开源仓库 `zh-ste-lint`，与本地技能同源同版本。
验证命令：`cd zh-ste-lint && npm test`（7 项断言，2026-10-26 实测 ALL PASS）。

## 九、延伸认知

AI 输出格式可以排成阶梯：**受控语言 → 画图 → HTML → 讲解视频**，越往后越直观。
本技能的五条只是第一级；当任务涉及"让人看懂一个结构/流程"时，
优先建议用图示或交互页面替代长文。
